## Latency: the waiting is the model, not the ERP

| Measure | Value |
|---|---|
| Time to first word, median | **3.0 s** |
| p90 / worst | 5.1 s / **8.0 s** (T1, first turn) |
| Tool time (ERP calls) | 40–320 ms per call, under 0.6 s per turn |
| Model time | roughly 1.5–3 s **per model step**; a turn with tools takes 2–4 steps |

**Finding 1: in most turns the first word comes at the very end of the turn.** "First word" ≈ "total" in 13
of 18 turns: the agent runs all its tools in silence, then speaks. The three exceptions show what's possible:
T6 turn 1 spoke after 0.56 s, T2 turn 1 after 0.66 s and T4 turn 1 after 1.0 s, because the model said something
before calling tools. The worst turn (T1 turn 1, 8.0 s) is three sequential model steps
(`identify_caller` → `check_products` → `create_draft_order`) before a single word.

**Finding 2: every model step re-reads about 27k tokens.** A turn with no tools at all (T5 turns 2–3) still sends
27k input tokens: system prompt plus tool definitions. Turns with tools reach 50–108k. The prompt cache covers
88% of input, so it's cheaper than it looks, but those tokens still slow down each step.
`identify_caller` returns about 3 kB per call (the full client card); the other tools return under 0.7 kB.

## Cost

About **207k input (88% cached) and 770 output tokens per call**: 1.25M → 4.6k tokens for the whole run of six
calls. There's a special prize for the lowest cost per successful call, so this number is worth tracking.
